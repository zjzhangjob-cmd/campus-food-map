# 觅食 · 社区生活地图产品介绍手册

## 1. 产品一句话

觅食是一款基于 AI 的社区生活美食地图，把“今天吃什么”从单纯搜餐厅，升级为结合位置、偏好、社区评价和下一步行程的智能决策体验。

## 2. 产品定位

觅食面向城市社区、高校、办公区和商圈用户，解决用户在日常吃饭场景里的三个问题：

1. 不知道吃什么：选择太多、信息太杂、推荐不贴合。
2. 不知道去哪吃：距离、路线、地铁、商场、后续安排没有被一起考虑。
3. 不知道靠不靠谱：平台评分抽象，缺少附近真实用户的经验反馈。

觅食的核心不是再做一个餐厅列表，而是做一个“会问问题、懂位置、能规划”的本地生活 AI 助手。

## 3. 核心用户场景

### 场景一：快速决策

用户只需要说：“附近预算30，不吃辣，想清淡一点。”

小觅会综合预算、口味、距离、评分和社区热度，给出少量高匹配餐厅，并支持加入心愿单或地图。

### 场景二：空间选择

用户说：“吃完我要去地铁，别绕路。”

地图小觅会把用户位置、餐厅点位、地铁站或商场等关键位置一起纳入判断，帮助用户从“好吃”进一步选择“顺路、方便、适合下一步安排”。

### 场景三：社区种草

用户想知道附近真实反馈，可以进入社区圈查看热帖、探店、评价和求推荐内容。社区内容会反向影响推荐，让推荐不只依赖冷冰冰的评分。

### 场景四：持续比较

用户可以把感兴趣的餐厅加入心愿单，后续批量放到地图上，一键规划路线，比较距离、价格、环境和行程便利性。

## 4. 产品核心功能

### 小觅 Agent

- 支持自然语言输入，理解预算、口味、人数、忌口、心情和场景。
- 信息不足时会追问，不会每次都机械推荐。
- 推荐后支持二次纠偏，比如“太贵了”“不吃辣”“换近一点”“保留第二家”。
- 能回答产品使用问题，比如社区圈、心愿单、地图页、评价和详情页怎么用。

### 全屏生活地图

- 支持自动定位和地点搜索。
- 按当前位置或搜索地点推荐附近餐厅。
- 餐厅以地图点位、气泡卡片和距离线结合呈现。
- 可结合地铁站、商场、展会、停车点、回家方向等做空间规划。

### 社区圈

- 支持附近用户发帖、评论、点赞和求推荐。
- 用真实探店反馈补充餐厅评分。
- 帮助用户理解“这家为什么被推荐”和“附近人怎么评价”。

### 心愿单

- 统一承接收藏功能。
- 首页餐厅卡、帖子餐厅、小觅推荐卡、地图点位都可以加入心愿单。
- 支持逐个选择、批量加入地图和一键规划。

## 5. 产品亮点

1. 从餐厅推荐到生活决策  
   觅食不仅推荐餐厅，还会结合用户的下一站、交通方式、是否要办公、自习、聚餐、带娃等真实情境。

2. 普通 Agent 与地图 Agent 双形态  
   普通小觅负责需求挖掘和卡片推荐，地图小觅负责空间规划和路线比较。

3. 推荐更可解释  
   小觅会说明为什么推荐、有什么风险、如何继续收窄，而不是只给出列表。

4. 社区反馈参与推荐  
   通过社区圈，把附近真实评价、热帖和探店内容纳入用户决策。

5. 心愿单形成闭环  
   从种草、收藏、比较到地图规划，用户可以持续管理自己的候选餐厅。

## 6. 技术与实现

- 前端：HTML5、CSS3、Vanilla JS、高德地图 JS API。
- 后端：Python、FastAPI、SQLAlchemy、SQLite。
- AI：豆包 Seed 模型 / Claude API，可在无模型时回退到本地规则推荐。
- 数据：内置上海、广州等区域餐厅数据，包含菜系、价格、评分、标签、坐标和场景信息。
- 训练评测：建立 1000 条小觅 Agent 评测集，覆盖普通推荐、地图规划、边界问答和产品功能问题。

## 7. 参赛表达重点

评委最容易记住的表达：

“我们不是做一个更花哨的餐厅列表，而是让 AI 帮用户把吃饭这件小事，和位置、社区、路线、预算、偏好一起想清楚。”

## 8. 推荐演示动线

1. 首页输入：“附近预算30，不吃辣，想清淡一点。”
2. 展示小觅通过多轮理解给出推荐。
3. 点击进入全屏地图，展示用户位置、餐厅点位、距离和地图卡片。
4. 打开心愿单，把候选餐厅加入地图比较。
5. 切到社区圈，展示附近真实评价和热帖。
6. 结尾强调：小觅让本地生活推荐从“搜索”变成“理解和规划”。
